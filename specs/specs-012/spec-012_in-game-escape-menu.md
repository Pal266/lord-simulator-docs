# Title

In-Game Escape Menu

# Type

feature

# Description

Replace the loaded-plot Escape shortcut that currently opens the region overview with a dedicated in-game menu. The menu offers five localized actions in a fixed order: Save Game, Load Game, Settings, Main Menu, and Exit. The first three actions remain unavailable; Main Menu returns to the existing production main menu, and Exit closes the application normally. M continues to open the region overview. Reuse the game's approved main-menu button presentation, with enough width for every supported translation.

# Requirements

1. **Escape and M behavior.** While a plot is loaded and no higher-priority menu or modal is open, pressing `Escape` MUST open the in-game menu instead of the region-selection overview. Pressing `M` in that same state MUST continue to open the existing 100-cell region-selection overview with its existing selection and loading behavior. `Escape` MUST NOT open both screens, and repeated key input MUST NOT create duplicate in-game menus. Pressing `Escape` while the in-game menu is open MUST dismiss it and return to the same loaded plot without resetting its camera or reloading the level. While the in-game menu is open, `M` MUST NOT open the region overview. `Escape` on the region-selection overview MUST retain its existing context-sensitive Back behavior (dismiss the overview to the current plot when a plot is loaded; return to the main menu when opened before a plot is loaded). `Escape` while the initial main menu is displayed MUST retain its existing behavior. An in-progress plot load MUST NOT be interrupted or replaced by the in-game menu; existing region-selection input locking and load-failure behavior MUST remain intact.

2. **Menu ownership and input.** Implement the in-game menu as a production UMG Widget Blueprint backed by a C++ class derived from the established `ULordSimulatorActivatableWidget` base, and display it on the canonical CommonUI `Menu` layer of the existing primary UI root. Use the C++ class name `ULordSimulatorInGameMenuWidget` and Widget Blueprint asset path `/Game/UI/Screens/InGameMenu/WBP_InGameMenu`. C++ MUST own action handlers and menu lifecycle; the Blueprint MUST own the visual layout and approved asset references. The menu MUST consume UI input and prevent free-camera translation, rotation, movement-speed changes, and other plot commands while it is open. Closing it MUST restore the prior plot's input and focus normally without rebuilding the root UI or changing game/simulation time. The menu MUST open and close entirely within the existing application window.

3. **Five buttons and states.** Display exactly five buttons in this strict top-to-bottom order: **Save Game**, **Load Game**, **Settings**, **Main Menu**, **Exit**. **Save Game**, **Load Game**, and **Settings** MUST be visible, disabled, non-focusable, non-activatable, and permanently rendered in the approved disabled visual state. They MUST NOT respond to pointer hover with an enabled visual state, display placeholder messages, or open placeholder screens. **Main Menu** and **Exit** MUST be enabled, focusable, and actionable by pointer and the application's established keyboard UI activation behavior. Initial keyboard focus on opening the menu MUST be on **Main Menu**. Do not add a Resume, Back, title, confirmation button, tooltip, footer, or any sixth control; `Escape` is the sole menu-dismiss shortcut.

4. **Approved button assets and style.** Reuse the following exact approved source assets from the documentation repository: `visuals/approved/main-menu/main-menu-button-normal.png`, `visuals/approved/main-menu/main-menu-button-hover.png`, `visuals/approved/main-menu/main-menu-button-pressed.png`, and `visuals/approved/main-menu/main-menu-button-disabled.png`. Use their existing imported Unreal textures at `/Game/UI/Textures/MainMenu/T_MainMenuButtonNormal`, `/Game/UI/Textures/MainMenu/T_MainMenuButtonHover`, `/Game/UI/Textures/MainMenu/T_MainMenuButtonPressed`, and `/Game/UI/Textures/MainMenu/T_MainMenuButtonDisabled`, respectively. Reuse the existing main-menu button presentation/style (including enabled-normal, hover/focus, pressed, and disabled state mappings), the built-in Roboto Regular font at 32 Slate units at the reference viewport, centered labels, and label colors `#E7D9B8` (normal), `#FFF0C7` (hover/focus), `#D8B56C` (pressed), and `#777777` (disabled). Do not modify or replace the approved texture source assets, introduce new art or fonts, tint the button artwork, or add label shadows, outlines, effects, or animations. Reuse the established main-menu button class where appropriate rather than introducing an independently styled button system.

5. **Layout and translated-text fit.** Show the loaded plot behind the in-game menu; do not display the main-menu background image, add a dimming panel, or introduce other background art. Arrange all five equal-size buttons in one vertical stack centered both horizontally and vertically within the game viewport; the stack as a whole MUST remain centered when the viewport dimensions or language change. At the `1920 × 1080` reference viewport before the project's normal Unreal DPI scaling, use a desired button size of `560 × 179` Slate units and `8` Slate units between consecutive button slots, with no fixed left or right offset. The `560`-unit width intentionally expands the existing button presentation to accommodate the longest translation; horizontal scaling of the button brush is permitted **for this new in-game menu only**, without changing the approved texture files or existing main-menu button dimensions. Keep button labels on a single centered line with at least `24` Slate units of horizontal inset on each side at reference size, and do not truncate, clip, or replace labels with ellipses. Preserve the project's existing DPI-scaling policy; if the full five-button stack would exceed the available viewport, uniformly shrink the stack (including fonts and spacing) enough to keep every button fully onscreen, with at least `24` Slate units of inset from the viewport edges. The screen MUST remain usable at `1280 × 720`, `1920 × 1080`, `2560 × 1440`, `3440 × 1440`, and `3840 × 2160` in all supported cultures, without a new DPI curve or resolution-specific alternate design. Changes to widths/layout MUST NOT affect the existing main-menu screen.

6. **Localization.** Add the following exact entries to the canonical Lord Simulator String Table `/Game/Localization/ST_LordSimulator` and its existing Unreal localization resources. The visible labels MUST use localization-aware `FText` and update correctly under the established language framework. These new keys are specific to the in-game menu and MUST NOT rename or alter the existing main-menu keys or translations.

   | Key | English (`en`) | Czech (`cs`) | Ukrainian (`uk`) |
   |---|---|---|---|
   | `InGameMenu.SaveGame` | `SAVE GAME` | `ULOŽIT HRU` | `ЗБЕРЕГТИ ГРУ` |
   | `InGameMenu.LoadGame` | `LOAD GAME` | `NAČÍST HRU` | `ЗАВАНТАЖИТИ ГРУ` |
   | `InGameMenu.Settings` | `SETTINGS` | `NASTAVENÍ` | `ПАРАМЕТРИ` |
   | `InGameMenu.MainMenu` | `MAIN MENU` | `HLAVNÍ MENU` | `ГОЛОВНЕ МЕНЮ` |
   | `InGameMenu.Exit` | `EXIT` | `UKONČIT` | `ВИЙТИ` |

   Gather, compile, and package the localization resources for `en`, `cs`, and `uk` through the existing workflow. Do not add other player-facing text, localization keys, or cultures.

7. **Main Menu action.** Activating **Main Menu** MUST end the current plot-viewing session *without closing the application*. Safely dismiss the in-game menu, unload the currently streamed plot and its water/content, release the plot camera and plot-specific input, clear any pending/current region-selection session state, and present exactly one instance of the existing production `/Game/UI/Screens/MainMenu/WBP_MainMenu` on the canonical `Menu` layer. Restore normal main-menu input and focus. This is navigation to the main menu, not an application restart: do not repeat global initialization, recreate the primary UI root, reset settings, or change the active language. After returning, **New Game** MUST again open the standard region-selection overview and allow any plot to load normally; no stale selection/menu state, duplicate widgets, residual landscape, or stale camera may remain. Ensure this return flow works even though the initial main-menu widget was dismissed when the first plot loaded. No save or confirmation dialog is added, and no game-save data is written.

8. **Exit action.** Activating **Exit** MUST request a normal Unreal application quit through the same kind of engine/platform-safe mechanism used by the existing main-menu Quit command. In a packaged Win64 build, it MUST close the application and permit the canonical Lord Simulator shutdown lifecycle, including required settings comparison/persistence and logging. In Unreal Editor PIE, it MUST end only the play session, not intentionally terminate the Editor process. Do not use forced process termination or show a confirmation dialog.

9. **Scope and preservation.** Do not implement saving, loading saved games, or the Settings screen; the three corresponding buttons remain disabled. Do not alter terrain generation, level geometry, water, M-based plot selection, plot-switching semantics, localization framework architecture, the main menu's approved production appearance, the application's startup sequence, or existing shutdown semantics. Do not add game-time progression, pause simulation time, create new persistent settings, add project log messages, introduce third-party dependencies, or add sound, animation, or decorative UI elements as part of this feature. Existing localization, UI navigation, and other behavior outside the explicitly changed Escape/return-to-menu flow MUST remain unchanged.

10. **Tests and build verification.** Add deterministic Unreal Automation coverage for `Escape` opening exactly one in-game menu from a loaded plot, `Escape` closing it without changing the current level/camera, `M` still opening the region overview, `M` not opening the overview over the in-game menu, the overview's existing `Escape` dismissal, disabled/non-focusable actions, the two enabled commands, and the correct five localization keys and button order. Test return-to-main-menu state cleanup and the ability to initiate a fresh New Game/plot load; the quit command MUST be tested through a non-terminating test seam rather than ending the automation run. Keep existing automation tests passing. Build the standard Win64 Development Editor target and a Win64 Shipping package; verify the menu's appearance, button layout and text in `en`, `cs`, and `uk` at all five specified viewport sizes. Verify normal return-to-main-menu/new-game and Exit behavior in the packaged build, and the Exit behavior in PIE. Verify that all required UI and localization assets are cooked into the installed game. Update the game project's `README.md` only if the actual build, test, localization, or packaging workflow changes.

11. **Project-standard update.** Update `standards/PROJECT_STANDARD.md` in the documentation repository to replace the current project-wide rule that both `M` and `Escape` open region selection from a loaded plot. The updated rule MUST state that `M` opens region selection and `Escape` opens the in-game menu, with `Escape` dismissing that menu; it MUST record the in-game menu's canonical `Menu`-layer ownership and the return-to-main-menu session cleanup behavior. Preserve the overview's existing context-sensitive `Escape` Back behavior. Do not alter unrelated project standards. This specification MUST NOT be considered complete until implementation and the project standard agree.

# Acceptance Criteria

1. From a loaded plot, `Escape` opens exactly one five-button in-game menu, never the region overview; `Escape` again closes the menu and restores the same camera/plot. `M` continues to open the region overview and cannot open it above the in-game menu. The overview's own `Escape` behavior and loading locks remain correct.
2. Buttons appear in the exact order Save Game, Load Game, Settings, Main Menu, Exit. The first three are disabled and non-focusable and perform no action. Main Menu and Exit work through pointer and established keyboard activation, with initial focus on Main Menu.
3. The menu uses the exact existing approved button artwork and established button-state/text style; the in-game menu alone uses the specified widened, responsive, horizontally and vertically centered button layout. All translated labels are completely visible and readable at each required viewport size, and the loaded plot remains visible behind the controls.
4. The five `InGameMenu.*` keys display their exact specified English, Czech, and Ukrainian text using the canonical localization resources, including in the packaged Windows build; existing main-menu localization is unchanged.
5. Main Menu cleanly unloads the plot and camera, returns to exactly one existing main-menu screen without restarting the application, and allows New Game and a subsequent plot selection to work again without residual state.
6. Exit closes a packaged Windows game through normal Unreal shutdown, preserving the canonical shutdown lifecycle; in PIE it ends only the play session and never intentionally kills the Editor. No confirmation is displayed.
7. No save/load functionality, Settings screen, new gameplay time behavior, visual assets, third-party dependencies, persistent settings, project log messages, or unrelated behavior changes are introduced.
8. Required Unreal Automation tests pass together with existing tests; Development Editor and Win64 Shipping builds succeed; the packaged application includes required UI/localization resources and passes the specified navigation, resolution, and language checks.
9. `standards/PROJECT_STANDARD.md` reflects the verified revised `M`/`Escape` behavior, in-game menu ownership, and return-to-main-menu lifecycle before the specification is marked complete.
