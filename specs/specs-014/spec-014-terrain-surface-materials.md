# Title

Southern Coast Range Terrain Surface Materials

# Type

feature

# Description

Replace the Southern Coast Range's uniform grey verification material with coherent, natural, license-safe textured ground. The existing scientific terrain generator already exports eight geographically coherent, smoothly blended ground-layer weightmaps, but the Unreal importer currently ignores them. Use those precise masks and eight explicitly selected CC0 PBR surfaces to show the region's western glaciated mountains, central foothills, eastern temperate plain, forest ground, alpine meadow, wet meadows, gravel, and river/lake beds. This changes terrain appearance only; it does not add vegetation meshes, seasons, gameplay, or modify terrain and water geometry.

# Requirements

1. **Source-of-truth investigation and preserved region.** Work from the established `southern_coast_range` generation and import pipeline in the documentation and game repositories. The current game importer `Source/LordSimulatorEditor/Private/LordSimulatorImportRegionCommandlet.cpp` creates and assigns `/Game/Maps/SouthernCoastRange/M_TerrainVerification`, an opaque grey `(0.45, 0.45, 0.45)` material with roughness `1`, and does not consume the generated `layer_*.png` exports. The authoritative source is `fictional_map/regions/southern_coast_range/scripts/detail_plots.py`, which exports **eight 8-bit 4033 × 4033 weightmaps per tile**; its masks are based on modelled treeline, slope, floodplain, glacial/outwash and water proximity, and sum to 255 per vertex. The 100 km square comprises an old wet-temperate mountain range in the west, foothills, and an eastern river plain. The generated ground classes, in exactly their source-layer spelling, are `rock`, `scree`, `alpine_meadow`, `forest`, `wet_meadow`, `gravel`, `riverbed`, and `lakebed`. No permanent glacier/snow layer is exported. No forest trees or other foliage geometry is implied by the `forest` ground mask. Do not invent new biomes, climate masks, procedural random biome distribution, or replace the source's established classifications. Preserve all 100 existing 10 × 10 km landscapes, their original 16-bit height values and transforms, river/lake actors and geometry, regional mapping, UI, and camera behavior.

4. **Deterministic source masks and provenance.** For every `tile_x{col}_y{row}` with `col,row = 0..9`, use exactly `fictional_map/regions/southern_coast_range/export/tile_x{col}_y{row}/layer_<layer>.png` from the same validated seed-7 generation run as that tile's saved `heightmap.png` and `water.json`. Compare shared-edge weights for every adjacent tile and require equality in geographic order. Ensure the generated input digests match the generation manifest before modifying assets. Fail preparation on missing, corrupt, mismatched, mixed-run, or incorrectly ordered data. Do not recalculate the science model or invent substitute masks on the fly. 5. **Production Unreal texture and landscape assets.** Import each approved source image once (not once per plot) into `/Game/Maps/SouthernCoastRange/Textures/` with fixed names `T_<Layer>_BaseColor`, `T_<Layer>_Normal`, and `T_<Layer>_Roughness` where `<Layer>` is `Rock`, `Scree`, `AlpineMeadow`, `Forest`, `WetMeadow`, `Gravel`, `Riverbed`, or `Lakebed`. BaseColor uses sRGB on and a color-appropriate texture compression; Normal uses sRGB off, normal-map compression, and the supplied **DX** (not GL) normal orientation; Roughness uses sRGB off and masks/grayscale-appropriate compression. Generate/import standard mips. Use opaque PBR shading, metallic `0`, no opacity, no terrain displacement, no tessellation, and no unsupported third-party runtime material system. Create one shared eight-layer Landscape material at `/Game/Maps/SouthernCoastRange/Materials/M_TerrainSurface` and eight weight-blended `ULandscapeLayerInfoObject` assets under `/Game/Maps/SouthernCoastRange/Layers/LI_<layer>`. Names on layer info and in the material MUST match the eight exported lowercase snake-case names exactly. Each layer uses its specified color, DX normal and roughness maps; layer mixing uses the imported weights, without thresholds, posterization, independent random masks, or painted manual overrides. Distinct layer contributions blend smoothly through the source weights, including correct normal re-normalization. The verification material may remain as an unused historical/debug asset, but NO production Landscape may continue to use it.

6. **Texture projection and continuity.** All image samples are repeat-wrapped and aligned to each tile's existing local landscape X/Y coordinate in metres, with exactly the XY texture periods specified in Requirement 3: `UV = local_xy_metres / period_metres`. The 10,000-metre tile width is an exact whole-number multiple of each specified period, so opposite tile edges use matching UV phases; do not introduce tile-dependent random rotations, hue changes, or scaling. On steep `rock` and `scree` faces, use aligned three-axis world/object-position texture projection of the respective maps with blend weights proportional to `abs(surface_normal.xyz)^4`, normalized to sum to 1, to avoid conspicuous planar stretching; use the same declared horizontal period and metre-based Z scale. Non-steep terrain layers use X/Y projection. Keep the same texture color-space and material parameters throughout all 100 plots and use no actor-specific tint. Do not create extra broad-scale splat masks that change the scientific layer distribution. At plot edges, verify the shared-edge weightmap samples and texture UV phase for the adjacent tile pair; test terrain seams without changing heights or adding skirts.

# Acceptance Criteria

1. The eight explicitly user-approved Poly Haven CC0 texture sets are represented by the exact 24 immutable original 2K channel files at the listed `visuals/approved/terrain/southern-coast-range/` paths. All dimensions, channel formats and SHA-256 hashes match the accompanying source/creator/license provenance manifest; no unapproved or invented production visuals are used.
2. All 100 plots have the eight source-generated, reproducible 4033 × 4033 grayscale weightmaps from the same validated generation run; all 800 maps pass dimensions/format/total-weight and shared-edge validation, and the manifest covers their hashes.
3. Each of the 100 Landscape levels uses the same `/Game/Maps/SouthernCoastRange/Materials/M_TerrainSurface` and exact eight weight-blended layers/approved PBR image sets; no loaded Landscape uses the uniform grey verification material.
4. Material blending and UV/projection rules are implemented exactly; rock faces do not use obviously stretched flat planar projection, neighbouring edges align, and source-driven alpine/forest/scree/wet/gravel/waterbed distributions are visibly coherent without introducing unsupported terrain classes.
5. Existing terrain heights, transforms, water actors and outlines, lights, map/plot IDs, selection controls and camera state are unchanged by updating materials; rerunning the update is idempotent and source-driven future tile imports do not revert to grey.
6. Representative mountain, foothill, plain, water-margin and neighbouring-edge tests pass with screenshots at all three navigation distances. Source, cooked material and layer data are available offline in the packaged and installed game without internet/Python requirements at runtime.
7. Required deterministic checks, existing applicable tests, Development Editor and Win64 Shipping packaging/installation checks pass; if resource or shader limits prevent this, the implementation is explicitly reported blocked rather than substituted or represented as complete.
8. `README.md` and `standards/PROJECT_STANDARD.md` document the verified resulting material, approved-asset provenance and deterministic offline import workflow consistently.
